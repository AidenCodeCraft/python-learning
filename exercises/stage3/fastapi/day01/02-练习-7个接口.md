## 第 1 题 · `GET /`

**在练什么**：装饰器登记路由 + 返回 dict 自动变 JSON。

**从哪开始**：只需要 `return` 一个 dict。

```python
@app.get("/")
def read_root() -> dict[str, str]:
    # TODO：return 一个包含 message 键的字典，值是 "Hello FastAPI"
    return {}
```

**预期**：状态码 `200`，body `{"message": "Hello FastAPI"}`

**常见错误**：
- 写成 `return "Hello FastAPI"` → 返回的是 JSON 字符串 `"Hello FastAPI"`，不是对象
- 忘了 `@app.get("/")` → 404

**预期**：状态码 `200`，body `{"status": "ok"}`

## 第 4 题 · `GET /items/{item_id}`（先做这个）

**在练什么**
1. **路径参数**：URL 里的 `{item_id}` 传给函数参数
2. 类型注解 `int` 让框架自动转换（传 `abc` → 422）
3. 不存在时 `raise HTTPException(404, "Item not found")`

**从哪开始**

```python
@app.get("/items/{item_id}", response_model=Item)
def get_item(item_id: int) -> dict:
    # 1. 判断 item_id 在不在 ITEMS 里（dict 的 in）
    # 2. 不在 → raise HTTPException(status_code=..., detail="Item not found")
    # 3. 在 → return ITEMS[item_id]（模型会自动过滤 secret）
    return {}
```

**预期**
| 请求 | 状态码 | body |
|---|---|---|
| `GET /items/1` | 200 | `{"id":1,"name":"Python 入门书","price":99.0,"stock":5}`（**没有 secret**） |
| `GET /items/999` | 404 | `{"detail":"Item not found"}` |
| `GET /items/abc` | 422 | 框架自动返回，**你不用写任何代码** |

**常见错误**：
- `return {"id": 1}` 写死数据（要用 `ITEMS`）
- 用 `return {"detail": "Item not found"}` 代替 raise → 状态码是 200，自检会挂
- 404 用了字符串 `status_code="404"` → 用整数或 `status.HTTP_404_NOT_FOUND`

## 第 3 题 · `GET /items`（分页 + 过滤）

**在练什么**
1. **查询参数**：`skip`、`limit` 有默认值 → 自动是查询参数
2. 分页 = 列表切片
3. `response_model=list[Item]` 把 secret 全部过滤

**从哪开始**

```python
@app.get("/items", response_model=list[Item])
def list_items(skip: int = 0, limit: int = 10) -> list[dict]:
    # 1. 按 id 升序取出所有商品： [ITEMS[i] for i in sorted(ITEMS)]
    # 2. 切片： ordered[skip : skip + limit]
    return []
```

**预期**
| 请求 | 状态码 | body |
|---|---|---|
| `GET /items` | 200 | 2 条，第一条 id=1，**无 secret** |
| `GET /items?skip=1&limit=1` | 200 | 1 条，id=2 |

**常见错误**：
- 忘了切片 → 分页不生效
- 用 `ITEMS.values()` 直接返回 → 顺序不保证（要先按 id 排序）
- 给 `skip` 加 `int | None = None` → 变成可选参数，默认值没了

## 第 5 题 · `POST /items`（创建）

**在练什么**
1. **请求体**：`payload: ItemCreate`，框架自动解析 JSON + 校验
2. 用全局 `next_id` 分配新 id
3. 返回 **201**

**从哪开始**

```python
@app.post("/items", response_model=Item, status_code=status.HTTP_201_CREATED)
def create_item(payload: ItemCreate) -> dict:
    # 1. 声明 global next_id（因为要修改模块级变量）
    # 2. 组一个新 dict：id=next_id, name/price/stock 从 payload 取
    # 3. 放进 ITEMS[next_id]，next_id += 1
    # 4. return 新商品（secret 会被 response_model 过滤）
    return {}
```

**预期**
| 请求 | 状态码 | body 关键字段 |
|---|---|---|
| `POST /items {"name":"鼠标","price":59.9}` | **201** | `id=3`、`stock=0`（默认值生效） |
| `POST /items {"name":"坏数据","price":-1}` | 422 | 框架自动返回 |
| `POST /items {"name":"","price":10}` | 422 | 框架自动返回 |

**常见错误**：
- 忘了 `global next_id` → `UnboundLocalError`
- 忘了 201（装饰器里已经写好了，别删）
- 自己手写 `if price <= 0` 判断（不需要，Pydantic 已经校验）

## 第 6 题 · `PUT /items/{item_id}`（局部更新，最容易卡）

**在练什么**
1. 只更新"用户传了的字段"（没传的保持原样）
2. `payload.model_dump(exclude_unset=True)` 是关键 API
3. 不存在 → 404

**从哪开始**

```python
@app.put("/items/{item_id}", response_model=Item)
def update_item(item_id: int, payload: ItemUpdate) -> dict:
    # 1. 不在 ITEMS → raise 404
    # 2. changes = payload.model_dump(exclude_unset=True)
    # 3. ITEMS[item_id].update(changes)   （只更新传了的字段）
    # 4. return ITEMS[item_id]
    return {}
```

**预期**
| 请求 | 状态码 | 结果 |
|---|---|---|
| `PUT /items/1 {"price":88.0}` | 200 | price 变 88.0，**name 保持不变** |
| `PUT /items/999 {"price":1.0}` | 404 | `{"detail":"Item not found"}` |

**常见错误**：
- 用 `payload.model_dump()`（不带 `exclude_unset`）→ 没传的字段变成 `None`，把 name 覆盖成 null
- 用 `exclude_unset` 后又过滤掉了 `None`（这里不需要过滤，传 `null` 也算用户意图）
- 直接 `ITEMS[item_id] = payload` → 丢了 id，response_model 校验失败（500）

---

## 第 7 题 · `DELETE /items/{item_id}`（删除）

**在练什么**
1. 204 = 成功但**没有 body**
2. `del ITEMS[item_id]`
3. 不存在 → 404

```python
@app.delete("/items/{item_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_item(item_id: int) -> None:
    # 1. 不在 → raise 404
    # 2. del ITEMS[item_id]
    # 3. return None（204 不能有 body，返回 dict 会报错）
    return None
```

**预期**
| 请求 | 状态码 |
|---|---|
| `DELETE /items/2` | 204 |
| `DELETE /items/999` | 404 |
| 删除后再 `GET /items/2` | 404 |

**常见错误**：
- 返回 `{"deleted": True}` → 204 不能有 body，会报错
- 忘了 `del`，只 return → 数据还在，自检挂
