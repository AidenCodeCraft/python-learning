## 一、Redis 考点



### 1. 数据类型与实操题

覆盖下面 **5类常见数据结构或功能**Redis 官方也按这些功能分别介绍。[Redis 数据类型文档](https://redis.io/docs/latest/develop/data-types/)

| 类型/功能               | 核心考点                                       | 参考命令                                                     | 可直接出的题                                         |
| ----------------------- | ---------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------- |
| **String 字符串**       | 读写、批量读写、计数、过期、条件写入           | `SET`、`GET`、`MSET`、`MGET`、`INCR`、`DECR`、`SET NX EX`    | 保存验证码并设置有效期；统计课程访问次数             |
| **Hash 哈希**           | 字段增删改查、批量设置、字段计数               | `HSET`、`HGET`、`HGETALL`、`HDEL`、`HEXISTS`、`HINCRBY`      | 保存学员资料，修改手机号，增加学习时长，删除临时字段 |
| **List 列表**           | 两端插入和弹出、范围读取、长度、元素修改与删除 | `LPUSH`、`RPUSH`、`LPOP`、`RPOP`、`LRANGE`、`LLEN`、`LSET`、`LREM`、`LTRIM` | 实现先进先出的任务队列；只保留最近 10 条学习记录     |
| **Set 集合**            | 去重、成员判断、集合运算                       | `SADD`、`SMEMBERS`、`SISMEMBER`、`SREM`、`SCARD`、`SINTER`、`SUNION`、`SDIFF` | 统计课程报名人数；查询同时报名两门课的学员           |
| **Sorted Set 有序集合** | 分数更新、排名、范围查询、删除                 | `ZADD`、`ZSCORE`、`ZINCRBY`、`ZRANGE`、`ZREVRANK`、`ZREM`    | 实现成绩排行榜，查询前三名和指定学员排名             |

3. Redis 必须设置的理解题

这些题能区分“会调用方法”和“理解数据结构”：

1. **String 与 Hash：** 保存学员资料时，各适合什么场景？
2. **List 与 Set：** 哪个允许重复？哪个保留顺序？
3. **Set 与 Sorted Set：** 成绩排行榜为什么适合使用有序集合？
4. **排行榜：** Redis 返回的排名从几开始？如何转换为界面显示的名次？
5. **Pipeline 与事务：** 批量发送命令与事务执行有什么区别？
6. **原子性：** Python 中先 `GET` 再 `SET` 实现计数，会有什么并发问题？

## 二、MySQL 考点

建议采用统一的“学员选课”场景，准备四张表：

| 表                 | 建议字段                                                     |
| ------------------ | ------------------------------------------------------------ |
| `students` 学员    | `id`、`name`、`age`、`phone`、`city`、`created_at`           |
| `courses` 课程     | `id`、`name`、`price`                                        |
| `enrollments` 报名 | `id`、`student_id`、`course_id`、`score`、`status`、`created_at` |
| `accounts` 账户    | `student_id`、`balance`                                      |

约定：手机号唯一、同一学员不能重复报名同一课程；未出成绩用 `NULL` 表示，金额使用 `DECIMAL`。

### 1. 增：INSERT

| 考点             | 出题任务                                   |
| ---------------- | ------------------------------------------ |
| 单条插入         | 新增一名学员                               |
| 批量插入         | 新增 10 名学员                             |
| 默认值与自增主键 | 新增课程并获取生成的主键                   |
| 唯一约束         | 重复插入手机号，捕获错误并回滚             |
| 插入查询结果     | 把符合条件的学员写入教师提供的归档表       |
| 冲突处理         | 对已存在的数据按指定规则更新，可作为进阶题 |

### 2. 查：SELECT

查询应占 MySQL 部分较大比重，建议覆盖以下层次：

| 层次       | 出题任务                             |
| ---------- | ------------------------------------ |
| 基础查询   | 查询学员姓名和城市，列出不重复城市   |
| 条件查询   | 查询指定城市且年龄满足条件的学员     |
| 范围与集合 | 查询年龄区间内、来自指定城市的学员   |
| 模糊查询   | 查询姓“张”的学员                     |
| 空值判断   | 查询尚未出成绩的报名记录             |
| 排序与分页 | 按报名时间倒序分页，同时间按主键排序 |
| 聚合       | 统计课程报名数、平均分和最高分       |
| 分组过滤   | 查询报名人数超过 5 人的课程          |
| 内连接     | 查询学员姓名、课程名称和成绩         |
| 外连接     | 查询所有学员，包括未报名学员         |
| 子查询     | 查询成绩高于该课程平均分的学员       |
| 无匹配记录 | 查询从未报名课程的学员               |
| 条件表达式 | 将成绩转换为优秀、及格、不及格       |

进阶班还可以加入 CTE、窗口函数，例如“查询每门课程成绩前三名”，并明确同分时的排名规则。

### 3. 改：UPDATE

| 考点         | 出题任务                                       |
| ------------ | ---------------------------------------------- |
| 单字段更新   | 根据学员编号修改手机号                         |
| 多字段更新   | 同时修改学员城市和年龄                         |
| 条件批量更新 | 将指定课程的待审核报名改为已通过               |
| 表达式更新   | 给指定课程价格统一增加 10%                     |

### 4. 删：DELETE

| 考点         | 出题任务                                             |
| ------------ | ---------------------------------------------------- |
| 单条删除     | 删除指定报名记录                                     |
| 条件批量删除 | 删除指定日期以前已取消的报名                         |
| 多条件删除   | 删除指定课程中状态为取消的记录                       |
| 关联数据处理 | 删除学员及其报名记录，按题目规定的事务或外键策略执行 |
| 逻辑删除     | 使用状态字段标记删除，查询时排除                     |

删除题使用教师提供的独立测试库，并明确允许删除的数据范围。

### 5. 事务与程序正确性

建议安排一道必考事务题：

> 学员报名课程时，需要扣减账户余额并新增报名记录。余额不足、重复报名或任一步骤失败时，整个操作回滚。

验收点：

- 两次写操作处于同一事务。
- 扣款不会导致余额为负。
- 重复报名由唯一约束兜底。
- 失败后账户余额和报名记录均保持正确。
- SQL 使用参数绑定，异常后释放连接资源。

## 三、Redis + MySQL 综合题

**题目：实现学员资料查询与更新。**

要求：

1. MySQL 保存学员资料。
2. 查询时先读 Redis，未命中再查询 MySQL。
3. 将查到的资料写入 Redis，有效期为 300 秒。
4. 修改资料时，先更新并提交 MySQL，再删除对应缓存。
5. 不存在的学员返回明确结果。
6. 正确处理 JSON、中文、数据库异常。

基础验收验证正常查询、缓存命中、修改后的查询结果；进阶追问并发情况下的缓存一致性问题。不要把这套基础流程当作强一致性保证。
