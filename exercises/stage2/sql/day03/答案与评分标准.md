**B6（5 分）**

```sql
SELECT d.name, COUNT(e.id) AS cnt
```

**B8（5 分）**


**B9（5 分）**

**⚠️ 连成 departments 的 0 分（这是本次你的错题）**

**B10（10 分）** 两种都对：

```sql
-- 写法 1：排序 + LIMIT
SELECT e.name, e.salary
FROM employees e
JOIN departments d ON e.dept_id = d.id
WHERE d.name = '研发部'
ORDER BY e.salary DESC
LIMIT 1;

-- 写法 2：相关子查询
SELECT e.name, e.salary
FROM employees e
WHERE e.dept_id = (SELECT id FROM departments WHERE name = '研发部')
  AND e.salary = (SELECT MAX(e2.salary) FROM employees e2 WHERE e2.dept_id = e.dept_id);
```

预期：**王强 32000**。评分：条件正确 5 / 取最大的写法正确 5

# Part C · 表设计题（25 分）

## 参考设计

**① 字段清单（10 分）**

| 表 | 字段 |
|---|---|
| `books` | id BIGINT PK 自增；title VARCHAR(200) NOT NULL；author VARCHAR(100) NOT NULL；isbn VARCHAR(20) NOT NULL UNIQUE；total_copies INT NOT NULL DEFAULT 0；available_copies INT NOT NULL DEFAULT 0 |
| `members` | id BIGINT PK 自增；name VARCHAR(50) NOT NULL；phone VARCHAR(20) NOT NULL UNIQUE；created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP |
| `borrow_records` | id BIGINT PK 自增；book_id BIGINT NOT NULL；member_id BIGINT NOT NULL；borrowed_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP；due_at DATETIME NOT NULL；returned_at DATETIME NULL；status TINYINT NOT NULL DEFAULT 0 |

**② 建表 SQL（10 分）**

```sql
CREATE TABLE books (
    id               BIGINT PRIMARY KEY AUTO_INCREMENT,
    title            VARCHAR(200) NOT NULL,
    author           VARCHAR(100) NOT NULL,
    isbn             VARCHAR(20)  NOT NULL UNIQUE,
    total_copies     INT NOT NULL DEFAULT 0,
    available_copies INT NOT NULL DEFAULT 0
);

CREATE TABLE members (
    id         BIGINT PRIMARY KEY AUTO_INCREMENT,
    name       VARCHAR(50) NOT NULL,
    phone      VARCHAR(20) NOT NULL UNIQUE,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE borrow_records (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    book_id     BIGINT NOT NULL,
    member_id   BIGINT NOT NULL,
    borrowed_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    due_at      DATETIME NOT NULL,
    returned_at DATETIME NULL,
    status      TINYINT NOT NULL DEFAULT 0,
    CONSTRAINT fk_borrow_book   FOREIGN KEY (book_id)   REFERENCES books (id),
    CONSTRAINT fk_borrow_member FOREIGN KEY (member_id) REFERENCES members (id)
);
```

评分：3 张表 3 / 主键自增 3 / 唯一约束（isbn、phone）2 / 外键 2

**③ 索引（5 分）**

```sql
-- ① 查某会员当前还没还的书
CREATE INDEX idx_borrow_member_status ON borrow_records (member_id, status);
-- ② 查某本书当前被谁借走了
CREATE INDEX idx_borrow_book_status ON borrow_records (book_id, status);
```

理由：
- 两个查询都是**按某个 id + 当前状态过滤**，把两列做成**联合索引**，`WHERE member_id = ? AND status = 0` 能直接命中（符合最左前缀）。
- `member_id` / `book_id` 是**外键列**，JOIN 和过滤都频繁，必须建索引。
- 不给 `status` 单独建索引：区分度太低（只有 3 个值），单独建意义不大，放进联合索引当第二列才合适。

评分：两条索引各 2 分 / 理由 1 分

# 本次模拟最可能失分的 5 个点（提前看）

1. **B6 用 `COUNT(*)` 而不是 `COUNT(e.id)`** → 财务部变 1
2. **B9 自连接连错表**（连 departments 而不是 employees）→ 上级变成部门名
3. **B3/B4 忘了 WHERE** → 全表更新/删除
4. **B8 的 HAVING 里不能写 `avg_salary` 别名**（MySQL 允许 `HAVING avg_salary`，但标准写法是 `HAVING AVG(...)`；用别名也行，看数据库）
5. **C 的外键命名/唯一约束漏掉** → 扣分
