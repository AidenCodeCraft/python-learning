## 三、讲解 1 · JOIN（上午 60 分钟）

### 1. 为什么需要 JOIN

数据是分表存的：`employees` 里只有 `dept_id`（数字），部门名在 `departments` 表里。
想显示"张伟属于研发部"，就得**把两张表连起来**。

```sql
SELECT e.name, d.name
FROM employees e                 -- e 是 employees 的别名
JOIN departments d               -- JOIN 默认就是 INNER JOIN
    ON e.dept_id = d.id          -- 连接条件：两边哪个字段相等
ORDER BY e.id;
```

**三个要素**：① 两张表 + 别名；② `ON` 连接条件；③ 选列时用 `别名.列名`（**必须**，因为两张表都有 `name`）。

### 2. INNER JOIN：只保留能匹配上的

```text
employees          departments
张伟 dept_id=1  ──► id=1 研发部     ✅ 匹配
周婷 dept_id=4  ──► id=4 人事部     ✅ 匹配
（假设有 dept_id=99 的员工）──► 没有 99 部门  ❌ 整行被丢弃
```

### 3. LEFT JOIN：左表全保留，右表没匹配的补 NULL

```sql
SELECT d.name, COUNT(e.id) AS cnt
FROM departments d
LEFT JOIN employees e ON e.dept_id = d.id
GROUP BY d.id, d.name;
```

结果里 **"财务部" 会显示 `cnt = 0`**（因为没有员工匹配）。
如果用 `INNER JOIN`，财务部**整行消失** —— 这是面试和考试最常考的区别。

> **注意 `COUNT(*)` 和 `COUNT(e.id)` 的区别**：LEFT JOIN 后财务部那一行 `e.id` 是 NULL，
> `COUNT(*)` 会数成 1（把 NULL 行也数了），`COUNT(e.id)` 才是 0。**统计左连接结果要用 `COUNT(右表.id)`。**

### 4. 几种 JOIN 速查

| 写法 | 保留什么 |
|---|---|
| `JOIN` = `INNER JOIN` | 两边都匹配的行 |
| `LEFT JOIN` | **左表全部** + 右表匹配的（没有则 NULL） |
| `RIGHT JOIN` | 右表全部 + 左表匹配的（很少用，改写成 LEFT JOIN 更清晰） |
| `FULL OUTER JOIN` | 两边都保留（**MySQL 不支持**，用 `UNION` 模拟） |

### 5. 自连接：一张表当两张用

员工表的 `manager_id` 指向同一张表的 `id`。查"员工 + 他的上级"：

```sql
SELECT e.name AS emp_name, m.name AS mgr_name
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id     -- 左连接：没有上级的人也要显示
ORDER BY e.id;
```

> 用 `INNER JOIN` 会丢掉 4 个没有上级的人（张伟/刘洋/杨帆/周婷），所以这里必须 `LEFT JOIN`。

### 6. 三个常见错误

| 错误 | 后果 |
|---|---|
| 忘了写 `ON` | **笛卡尔积**（12 × 5 = 60 行） |
| 把 LEFT JOIN 的条件写到 `WHERE` 里 | LEFT 被退化成 INNER（NULL 行被过滤掉） |
| 选列不写别名（`SELECT name`） | 报错 `Column 'name' in field list is ambiguous` |

## 五、讲解 2 · 子查询（下午 40 分钟）

### 1. 什么是子查询

**一条 SQL 里面再套一条 SELECT**，用括号包起来。按用途分三类：

### 2. 标量子查询（返回一个值）—— 最常用

```sql
-- 工资最高的员工
SELECT name, salary
FROM employees
WHERE salary = (SELECT MAX(salary) FROM employees);
```

括号里的查询**只返回一个值**，可以直接用 `=`、`>`、`<` 和它比。

### 3. `IN` 子查询（返回一列多个值）

```sql
-- 出现在 employees 表里的部门名
SELECT name
FROM departments
WHERE id IN (SELECT DISTINCT dept_id FROM employees WHERE dept_id IS NOT NULL);
```

### 4. `EXISTS` 子查询（判断"有没有"）

```sql
-- 没有员工的部门（EXISTS 写法）
SELECT d.name
FROM departments d
WHERE NOT EXISTS (SELECT 1 FROM employees e WHERE e.dept_id = d.id);
```

`EXISTS` 只关心"有没有结果行"，不关心具体值；这是**相关子查询**（引用了外层的 `d.id`）。

### 5. 子查询可以放三个位置

| 位置 | 例子 | 说明 |
|---|---|---|
| `WHERE` | `WHERE salary > (SELECT AVG(salary) ...)` | 最常见 |
| `FROM` | `FROM (SELECT ... ) AS t` | 当"临时表"用（派生表） |
| `SELECT` | `SELECT name, (SELECT ...) AS x` | 每行算一次（相关子查询，性能差，少用） |

### 6. JOIN 还是子查询？

| 场景 | 推荐 |
|---|---|
| 要显示另一张表的**列** | `JOIN` |
| 只要"**存在/不存在**"的判断 | `EXISTS` 子查询 |
| 和**聚合结果**比较（比平均高、比最高低） | 标量子查询 |
| 和**一列值**比较（在某个集合里） | `IN` 子查询 |

> 能用一个 `JOIN` 写清楚的，别硬套三层子查询（可读性和性能都差）。
