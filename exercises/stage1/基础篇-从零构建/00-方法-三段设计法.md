# 00 · 方法课：三段设计法（10-20 晚 · 40~50 分钟）

> **今晚任务**：给下面 3 个需求各写一张"设计卡"，**一行代码都不要写**。
> 目的：治"看到需求就直接伸手写代码"的习惯 —— 这是你 `todo_cli` 无从下手的直接原因。
> 这套方法在 ③改 和 ④造 两个阶段还要反复用。

---

## 三段设计法（每张卡照这个格式）

```markdown
## 需求 N：<名字>

### ① 数据长什么样？
（举一个具体例子；能用 JSON / 列表写出来最好）

### ② 分几个部分？各自职责一句话
（模块或函数，每个一句话，写清"谁不许干什么"）

### ③ 分几步做？（伪代码，5~8 步）
1. ...
2. ...
```

**判断标准只有一条**：别人拿着你这张卡，能不能直接写出代码、不用再问你。

---

## 需求 1：单词计数器

> 读一个文本文件，统计每个单词出现几次，打印出现最多的前 10 个。

要求写清楚：
- 数据用什么结构
- 分几个函数（读文件 / 数词 / 排序 / 打印）**各自负责什么、不许做什么**
- 要不要处理"文件不存在""标点符号""大小写"

---

## 需求 2：学生成绩管理（内存版，不存文件）

> 程序启动后可以：① 添加一个学生（姓名 + 分数）② 查看所有学生 ③ 打印平均分和最高分的学生。
> 这周先用"固定写死的几个操作"测试，不要求交互式输入。
> 例：添加("张三", 85) → 添加("李四", 92) → 查看 → 平均分 88.5 → 最高分 李四

要求写清楚：
- 一个学生用 dict 还是 class 表示？**说清理由**
- 学生列表怎么存
- 平均分怎么算（注意空列表的情况）

---

## 需求 3：简易 ATM（数据要存盘）

> 功能：存款、取款、查余额。余额要存到 JSON 文件，重启程序后还在。
> 规则：取款不能超过余额（超出就提示失败）；金额必须是正数。

要求写清楚：
- JSON 文件里存什么（举一个具体例子）
- 哪些函数要"读文件"，哪些函数要"写文件"
- 取款失败时函数返回什么（抛异常？返回 False？说清理由）
- 分几步做

---

## 提交格式

```text
【基础篇 00 · 设计卡】
## 需求 1：单词计数器
### ① 数据……
### ② 模块……
### ③ 步骤……

## 需求 2：……
## 需求 3：……
```

或者直接写进 `exercises/stage1/基础篇-从零构建/my_design.md` 再告诉我。

---

## 自检（交之前对一遍）

- [ ] 每张卡都有"数据示例"，不是抽象描述
- [ ] 每个模块都写了"职责 + 不许做什么"
- [ ] 伪代码 5~8 步，**每步一句话**，没有"然后实现细节"这种废话
- [ ] 需求 3 说清了"失败时返回什么"
- [ ] 全程没写 Python 代码（写了一点伪代码不算）

> 卡住很正常 —— 卡在哪一步，就在那张卡上写"我卡在这里 + 我的两种想法"，我会逐条批。
