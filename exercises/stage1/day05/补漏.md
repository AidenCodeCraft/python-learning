# Part A · Git 分支实操（15 分钟）

## A1. 为什么不能一直在 master 上改

真实公司流程：

```text
从 master 开分支 → 在分支上改代码 + 提交 → 提 PR → 代码审查 → 合并进 master
```

`master` 是"随时可以发布"的版本。**任何没经过审查的代码都不该直接提交到 master。**

## A2. 六个命令（全部要会用）

```powershell
git switch -c feat/todo-cli     # 从当前位置开新分支并切过去（旧写法：git checkout -b）
git branch                      # 列出所有分支，* 号是当前分支
git add . ; git commit -m "..." # 在分支上正常提交
git switch master               # 切回 master
git merge feat/todo-cli         # 把分支合并进当前分支（master）
git branch -d feat/todo-cli     # 删掉已合并的分支
```

看图（推荐一直用这个看历史）：

```powershell
git log --oneline --graph --all
```

## A3. 今天必须做的练习（就在 D5 项目上做）

```powershell
# 1. 开分支
git switch -c feat/todo-cli

# 2. 在分支上完成 todo_cli 项目（todo.py / cli.py / test_todo.py）+ pytest 全绿
# 3. 在分支上提交
git add .
git commit -m "feat(stage1): todo_cli 项目 + pytest（阶段 1 验收）"

# 4. 合并回 master
git switch master
git merge feat/todo-cli
git branch -d feat/todo-cli

# 5. 验收：图上应该能看到那条分支合并进来
git log --oneline --graph -8
```

> ⚠️ 注意：`git merge` 会做**快进合并**（fast-forward），历史里看不出"分支"的形状。
> 想在图上看到分叉可以用 `git merge --no-ff feat/todo-cli`（多一个合并提交）。**验收时用 `--no-ff` 更好看**。

## A4. 三个常见问题

| 现象 | 处理 |
|---|---|
| `git switch -c x` 报 already exists | 分支已存在 → `git switch x` |
| 在错的分支上提交了 | `git switch -c 正确的名字`（会把提交带过去），再把旧分支删掉 |
| `merge` 报冲突 | 阶段 1 不要求手解冲突 → `git merge --abort` 回到合并前，先问教练 |

# Part B · 装饰器认知（10 分钟）

> 你已经用过 `@classmethod`（micro_oop.py），但没学过它是什么。
> **阶段 3 的 FastAPI 你会天天写 `@app.get("/todos")`，所以必须"会读会讲"，不要求会写。**

## B1. 一句话

**装饰器 = 把函数当参数传进去、返回一个新函数的函数。**
`@f` 只是 **`g = f(g)`** 的语法糖。

## B2. 亲手跑一遍（在这个文件同目录新建 `try_decorator.py`）

```python
def shout(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs) + "!!"
    return wrapper


@shout
def greet(name: str) -> str:
    return "hi " + name


print(greet("Tom"))     # hi Tom!!
```

**关键**：`print(greet("Tom"))` 调用的其实不是原来那个 `greet`，而是 `shout` 返回的 `wrapper` ——
它先调用原 `greet` 拿到 `"hi Tom"`，再加 `"!!"`。

## B3. 你以后会遇到的三种

| 装饰器 | 在哪出现 | 作用 |
|---|---|---|
| `@app.get("/todos")` | 阶段 3 FastAPI | 把这个函数**注册成** GET 路由（FastAPI 内部靠它建路由表） |
| `@pytest.fixture` | 阶段 3/4 | 标记"这是一个测试用的准备函数"（`tmp_path` 就是内置 fixture） |
| `@classmethod` / `@staticmethod` | 已在用 / 会见到 | 让方法绑定到**类**而不是实例 |

## B4. 你现在只需要答对两问

1. `@f` 等价于什么写法？→ **`g = f(g)`**
2. 装饰器的参数和返回值分别是什么？→ **参数是函数，返回值也是函数**

> 不用会写装饰器。阶段 3 用 FastAPI 时，你会自然学会写（`@app.get` 就是写装饰器）。

# Part C · f-string（5 分钟）

```python
name = "Tom"
score = 92.456

print(f"{name} 得分 {score}")        # Tom 得分 92.456
print(f"{score:.2f}")                # 92.46        ← 保留 2 位小数（金额/统计常用）
print(f"{score:>8.1f}")              #     92.5     ← 右对齐占 8 格、1 位小数
print(f"{name=}")                    # name='Tom'   ← 调试神器：连变量名一起打
```

注意两点：

1. **字符串里要用别的引号包字典的 key**：`f"值={d['a']}"`（外层是 `"`，里面就用 `'`）。
2. **它只是字符串，不是模板引擎**：数字格式化可以，复杂逻辑别塞进去。

## 练习
