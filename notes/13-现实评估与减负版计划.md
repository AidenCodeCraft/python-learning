## 一、11-09 真实能做到什么（分层目标）

| 层级 | 目标 | 11-09 能否达到 |
|---|---|---|
| L0 能跑起来 | 装依赖、配环境、启动项目、看懂报错 | ✅ 能 |
| **L1 能改** | **照着现有代码改一个字段/接口/查询** | ✅ **能（这是上岗第一周的真实工作）** |
| **L2 能加** | **抄邻近接口，加一个简单接口（GET/POST + 校验 + 错误）** | ✅ 能（11-02~11-06 练） |
| L3 能设计 | 独立设计表结构/接口/分层 | ❌ 11-09 做不到（正常，入职 1~2 个月） |
| L4 能优化 | 性能、并发、缓存一致性、架构 | ❌ 远期（3~6 个月） |

**结论**：11-09 "开始承接公司简单需求" = **L1 + 部分 L2，并且有 AI 和同事协助**。
这不是妥协 —— 这就是大多数新人上岗第一周的真实状态。**你的目标是 L2，不是 L4。**

## 二、为什么现在会"脑袋浆糊"（三个原因，都是可修的）

### 原因 1：概念密度超过工作记忆（我的排期问题）

day02-redis 这一份里同时出现：**异步 redis 客户端 + 连接池 + lifespan + Depends + JSON 序列化 + TTL + 降级 + 限流** —— 8 个新概念。
人的工作记忆一次只能装 3~4 个新东西。**这不是你笨，是信息量超了。**

### 原因 2：前置知识缺口（教材问题）

你在 Python 里连 Redis 确实没系统学过：
- 10-23 只学了"Redis 命令 + 同步 redis-py 三行示例"（应试速成）
- 10-27 直接跳到"异步 + 框架集成" —— **跨了两级**

### 原因 3：没有消化时间（节奏问题）

每天一个新主题 + 新练习 + 新教材，**没有留"复习/消化/默写"的固定时间**。知识只能进"短期记忆"，第二天就糊。

## 三、减负三条原则（从现在起执行）

### 原则 1：一次只学一个主题

- 一天最多 **1 个新概念** + 复习旧概念
- 教材里"进阶/了解即可"的部分**明确标记，允许跳过**
- 停掉"并行多主题"（FastAPI + Redis + 补丁 + 默写同时上）

### 原则 2：先"抄用"，再"理解"

工作里允许"先会用"：
- 先**照着抄**跑通 → 能改 → 再问"为什么这样写"
- **理解放到复习时**（默写时自然就懂了）
- **不再要求"每个新概念当天吃透"**

### 原则 3：允许"暂时不懂清单"

建一个 `questions.md`（已建），最多记 5 条：
- 记下来 → 继续往下学 → 每天傍晚集中问
- **不懂不阻塞**。以前是"一卡住就停下来问 AI"，那会越卡越慢

## 五、Redis 降级：你现在只需要 3 件事

| # | 要什么 | 具体 | 时间 |
|---|---|---|---|
| 1 | 用**同步** redis-py 跑通 5 个命令 | set/get/hset/hgetall/incr（就 5 行） | 10 分钟 |
| 2 | 看懂"缓存三步" | 读缓存 → 没命中查库 → 写回 + TTL | 20 分钟 |
| 3 | 在 FastAPI 里**调用**现成封装 | 抄公司/脚手架的 `get_cache/set_cache`，不要求自己写 | 30 分钟 |

**`day02-redis` 里的异步客户端 / lifespan 连接池 / 限流 = 标记为"了解即可，11-09 后再学"。**
不是让你不学，是**现在不学** —— 上岗第一周你不会被要求写 Redis 连接池。

## 八、怎么判断"我在进步"（防焦虑）

每天只记 **3 行**（2 分钟）：

```text
10-28：今天会了 ___；卡在 ___；明天要 ___。
```

每周看一次曲线：
- 上周写不出的接口，这周能不能写？
- 诊断卷重做分数有没有涨？
- 闭卷能写出的最长代码从几行变成几行？

**不要拿"独立做项目"衡量自己** —— 那是 2~4 个月后的标准。
