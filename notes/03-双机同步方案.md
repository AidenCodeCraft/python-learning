# 03 · 双机同步方案（公司电脑 + 家里电脑）

> 更新时间：2026-10-14
> 结论速览：**代码走 Git；上下文走 `AGENTS.md`；聊天记录不用同步也不影响使用。**

---

## 一、先回答"为什么另一台电脑没有缓存记录"

这不是登录问题，是设计如此。

DSH 把会话数据**存在本机**：

```
C:\Users\<你的用户名>\.dsh\
├── sessions\                                  ← 会话历史（按工作区路径分目录）
│   └── --G-python-learning--\
│       ├── session.v4.jsonl.zstd              会话记录（zstd 压缩的 JSONL）
│       └── session-<uuid>\
├── storages\
│   ├── workspace.json                         工作区索引（记录绝对路径 → 会话 id）
│   └── session_projcache.json                 会话统计缓存
├── profiles\                                  桌面端 / Web 端插件与运行时
├── dsh-runtimes\                              DSH 自带运行时（Node 等）
├── .credentials.yaml                          ← 登录凭据（每台机器各自登录）
└── speech-to-text\
```

**登录（`deepseek-account-platform` 那个 token）只做身份认证，不搬会话数据。**
所以换台电脑登录，历史当然是空的。

本机现在的情况：
- 工作区 `G:\python-learning` 对应目录 `sessions\--G-python-learning--\`
- 里面有 1 个会话：`session-cbc1df9f-d8bf-473b-a562-9588b06b8150` + `session.v4.jsonl.zstd`（约 492 KB）

> 目录名是**工作区路径**编码来的：`G:\python-learning` → `--G-python-learning--`
> （规则：`:` `\` `/` 等连续非字母数字压成一个 `-`，非 ASCII 字符变 `~` + 大写十六进制，如 `G:\python学习` → `--G-python~5B66~4E60--`）

## 二、方案 A（推荐）：让上下文跟着仓库走，不依赖聊天记录

**核心机制**：DSH 的 `dsh-agent-instructions` 包会在**每个新会话的第一次请求**时，自动把下面这些内容塞进上下文：

1. 用户全局 `~/.dsh/AGENTS.md`
2. **项目链**：从项目根（以 `.git` 目录为标记）到当前工作目录，**每一级**的 `AGENTS.md` 和 `CLAUDE.md`，从宽到细
3. 本地覆盖（不进 Git）：`AGENTS.local.md`、`CLAUDE.local.md`

**所以：只要仓库根有一个 `AGENTS.md`，任何一台电脑、任何一个全新会话，一打开这个工作区就自动拿到全套教练上下文。**

这正是我这次已经给你做好的事 —— 仓库根已经有 [AGENTS.md](../AGENTS.md)，里面写了：

- 你是谁、你的背景、时间、公司技术栈
- 阶段 0 诊断结论（你的 9 个洞，按严重度排）
- 教学硬规则（含"三档推进不许跳档"、8 段反馈格式、5 级提示）
- **"每次新会话第一件事：读 `notes/`，然后先批改未批改的作答"**
- 当前进度表
- 环境约定 + 两个已知坑
- 仓库地图

**这条路的好处**：
- 不依赖聊天记录，不怕换机器、不怕会话删掉、不怕重装
- 版本化 —— 规则改了有 diff 可查
- 对**路径不敏感**：就算另一台电脑装不到 `G:\`，只要是一个 Git 仓库，`AGENTS.md` 照样生效

**唯一的动作**：在另一台电脑上，用 DSH 打开这个仓库目录，**新开一个会话**。
（注意：`AGENTS.md` 是在会话第一次请求时加载的，**当前这个会话不会重新加载**，必须新会话。）

### 可选：跨所有项目的个人偏好

如果你想让"我是谁、我的学习目标、我的作息"在所有项目里都生效，再放一份到用户全局：

```powershell
# 只放跨项目通用的部分，别把项目细节塞进来
notepad "$env:USERPROFILE\.dsh\AGENTS.md"
```

## 三、方案 B（可选，进阶）：把聊天记录也搬过去

只有"想在新电脑上翻到旧对话"时才需要。**不搬不影响学习和教学**（因为方案 A 已经覆盖上下文）。

### 搬运步骤

**第 1 步：两台电脑都退出 DSH**（DSH 运行时会写这些文件，热拷贝会冲突）

**第 2 步：导出（源机器）**

```powershell
$dst = 'D:\dsh-backup'          # 换成 U 盘或网盘目录
New-Item -ItemType Directory -Force -Path $dst | Out-Null

Copy-Item "$env:USERPROFILE\.dsh\sessions\--G-python-learning--" $dst\sessions -Recurse -Force
Copy-Item "$env:USERPROFILE\.dsh\storages\workspace.json"          $dst -Force
Copy-Item "$env:USERPROFILE\.dsh\storages\session_projcache.json"  $dst -Force
```

**第 3 步：导入（目标机器，先备份原有的）**

```powershell
$src = 'D:\dsh-backup'          # 换成实际来源目录
$dsh = "$env:USERPROFILE\.dsh"

# 3-1 备份现有数据
Copy-Item "$dsh\sessions" "$dsh\sessions.bak-$(Get-Date -f yyyyMMddHHmm)" -Recurse -Force
Copy-Item "$dsh\storages" "$dsh\storages.bak-$(Get-Date -f yyyyMMddHHmm)" -Recurse -Force

# 3-2 拷会话目录
New-Item -ItemType Directory -Force -Path "$dsh\sessions" | Out-Null
Copy-Item "$src\sessions\--G-python-learning--" "$dsh\sessions\" -Recurse -Force

# 3-3 合并 workspace.json（关键：把 G:\python-learning 这条记录并进去）
#     最简单做法是用编辑器手动把源机器的这一条 workspace 记录
#     和它的 sessionIds 贴到目标机器的 workspace.json 里
notepad "$dsh\storages\workspace.json"
```

### 四个必须知道的限制

| 限制 | 说明 |
|---|---|
| **项目路径必须一致** | 目录名和 `workspace.json` 里存的是**绝对路径**。目标是 `G:\python-learning` 才能直接合并；换成 `D:\python-learning` 就是另一个工作区，会话记录对不上 |
| **不要拷 `.credentials.yaml`** | 那是登录凭据，每台机器各自登录 |
| **不要两台同时开工** | 同一份会话数据被两边同时改会冲突。**一次只在一台机器上做，切换前先 push** |
| **用户名不同没关系** | `EDY` / `jiang` 都行，`~/.dsh` 是按当前用户解析的 |

## 四、代码同步：GitHub 在你这台机器上不通

我实测了（2026-10-14）：

| 站点 | 结果 |
|---|---|
| `github.com` | ❌ 超时 / `Recv failure: Connection was reset` |
| `ssh.github.com:443` | ❌ TLS 握手失败 |
| `gitee.com` | ✅ 200 |
| `gitcode.com` | ✅ 200 |
| `cnb.cool`（腾讯） | ✅ 200 |

而且 git 里已经配了一个 GitHub 远端：

```
origin  https://github.com/AidenCodeCraft/python-learning.git
```

在当前网络下**推不上去**。

### 三个选择

| 方案 | 适合 | 代价 |
|---|---|---|
| **① 换 Gitee（推荐）** | 没有稳定代理 | 5 分钟，一劳永逸 |
| ② GitHub + 代理软件 | 已经有稳定的代理（公司可能就有） | 要保证两台机器代理都稳定 |
| ③ 双远端 | 想同时留 GitHub 做备份 | 有代理时才推 GitHub |

### 方案 ① 操作步骤（Gitee）

```powershell
# 1) 先在 gitee.com 新建一个【私有】仓库，名字 python-learning
#    不要勾选"使用 Readme 初始化"，否则会有多余提交要处理

# 2) 把原来的 GitHub 远端改名保留（以后有代理还能用）
cd G:\python-learning
git remote rename origin github

# 3) 加上 Gitee 作为 origin
git remote add origin https://gitee.com/<你的Gitee用户名>/python-learning.git

# 4) 首次推送
git branch -M main
git push -u origin main
```

第一次推送会弹 Git Credential Manager 让你登录 Gitee（账号密码或私人令牌）。凭据会被 Windows 记住，以后不用再输。

> ⚠️ 仓库**设为私有**。后面阶段 2~5 会有数据库配置、`.env` 这类东西，虽然 `.gitignore` 已经挡了，但私有仓库更稳妥。

### 方案 ③ 双远端（两个都要）

```powershell
git remote set-url --add --push origin https://gitee.com/<你>/python-learning.git
git remote set-url --add --push origin https://github.com/AidenCodeCraft/python-learning.git
# 这样 git push 会依次推两个；GitHub 不通时会报错但 Gitee 已经推成功
```

## 五、第二台电脑的完整上车清单

```
□ 1. 装 DSH（版本 44.0.0，和这台保持一致），登录账号
      —— 会话历史是空的，正常，不用管

□ 2. 装 Python 3.13（安装时勾选 "Add python.exe to PATH"）
     装 Git
     装 Docker Desktop

□ 3. clone 仓库（路径尽量保持一致）
     git clone https://gitee.com/<你>/python-learning.git G:\python-learning

□ 4. 初始化环境（幂等，可以重复跑）
     cd G:\python-learning
     .\scripts\setup_env.ps1
     若提示"禁止运行脚本"：Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

□ 5. 用 DSH "打开工作区" → 选 G:\python-learning → 开一个新会话
     新会话会自动加载 AGENTS.md 和 notes/，教练上下文立刻到位

□ 6. 第一句话可以这么说：
     "读一遍 AGENTS.md 和 notes/，然后告诉我今天该做哪一天。"
```

> 如果第二台电脑盘符不同（比如只有 `D:`），**照样能用**：
> `git clone ... D:\python-learning` + 跑 `setup_env.ps1`，
> 方案 A 完全不受影响，只是**聊天记录搬不过去**（那本来也不重要）。

## 六、每天在两台电脑之间切换的标准动作

我已经写好一个脚本：[scripts/sync.ps1](../scripts/sync.ps1)

```powershell
cd G:\python-learning

# 开工前（换到另一台机器时）
.\scripts\sync.ps1 pull

# 看看现在能不能直接推送、有没有没提交的东西
.\scripts\sync.ps1 status

# 收工后
.\scripts\sync.ps1 push -Message "feat(stage1): day01 对象模型练习与错题"
```

**铁律**：
1. **开工先 pull，收工必 push。**
2. **一次只在一台电脑上写。** 两边同时改同一份文件，冲突会很难受。
3. 切机器前确认 `git status` 是干净的（`sync.ps1 status` 会告诉你）。

## 七、绝对不要同步的东西

| 东西 | 为什么 | 怎么办 |
|---|---|---|
| `.venv\` | 路径写死在虚拟环境里，换机器直接坏 | 每台机器跑 `setup_env.ps1` 重建（已在 `.gitignore`） |
| `.dsh\` 里的 `.credentials.yaml` | 登录凭据 | 各自登录 |
| `.env` / 数据库密码 | 安全 | 只提交 `.env.example`（已在 `.gitignore`） |
| `__pycache__\` / `.pytest_cache\` | 缓存噪音 | 已忽略 |
| `AGENTS.local.md` / `CLAUDE.local.md` | 机器专属的个人覆盖 | 已加入 `.gitignore`，故意不同步 |

---

## 八、一句话总结

> **代码 → Gitee 同步；教练上下文 → `AGENTS.md` 跟着仓库走；聊天记录 → 不用同步。**
> 换电脑后你要做的只有两件事：`git pull`，然后**新开一个 DSH 会话**。
