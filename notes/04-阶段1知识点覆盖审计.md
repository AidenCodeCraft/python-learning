## 三、缺口清单（按优先级）

### 🔴 P0 · Git 分支（必须补，15 分钟）

- **为什么必须**：notes/02 验收标准第 5 条写明"**能用 Git 完成分支 + 提交**（提交信息符合 `feat:` / `fix:` 规范）"。你目前 11 个提交全在 `master` 上，一条直线。
- **为什么重要**：真实的公司流程是"**开分支 → 改 → 提交 → 提 PR → 合并**"，不会让人直接推 `master`。11-09 你要上手公司需求，这是第一个动作。
- **补什么**：`git switch -c` / `git branch` / 切回 / `git merge` / 删分支 / `git log --graph`
- **在哪里练**：**明天 D5 的项目就用分支做**（见 [day05/补漏.md](../exercises/stage1/day05/补漏.md) Part A）

### 🟡 P1 · 装饰器认知（10 分钟）

- **为什么**：阶段 3 的 FastAPI 你会写 `@app.get("/todos")`，阶段 4 会写 `@pytest.fixture`；你已经用过 `@classmethod` 但没学过它是什么。
- **要求级别**：**认知级**（会读、能说清"装饰器 = 函数进、函数出"，不要求会写）。
- **补什么**：`@shout` 例子 + 三种常见装饰器的用途对照。

### 🟡 P1 · f-string（5 分钟）

- **为什么**：阶段 2 的统计/金额、阶段 4 的日志、项目里的 `__str__` 都会用；`f"{x:.2f}"` 是最常见的格式化。
- **补什么**：`f"{score:.2f}"`、`f"{d['k']}"`、`f"{name=}"`（调试神器）。

### 🟢 P2 · 随用随学（不必现在补）

| 项 | 什么时候会碰到 | 建议 |
|---|---|---|
| `*args` / `**kwargs` | 阶段 3 依赖注入、装饰器 wrapper | 遇到时 15 分钟补 |
| 继承 / `super()` | 阶段 4 SQLAlchemy 模型继承 `Base` | 阶段 4 前一天补 20 分钟 |
| `@staticmethod` | 遇到时 | 一句话即可 |
| uv 实操 | 阶段 3 起统一用 `uv`（notes/01 已定） | 阶段 3 第一天 20 分钟 |
| 断点调试 | 遇到复杂 bug 时 | 5 分钟演示（`breakpoint()`） |
