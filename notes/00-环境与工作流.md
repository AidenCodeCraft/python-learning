## 二、已修复的问题：工作区被 Windows 文件权限挡住

**现象**：AI 在本工作区执行任何命令都报 `grantWrite(G:\python-learning)` 失败。

**原因**：`G:\python-learning` 这个目录上缺少当前用户修改权限所需的口子（目录的所有者是当前用户，但缺少 `WRITE_OWNER`），导致沙箱无法为工作区发放写权限。

**处理**：用官方诊断脚本对该目录做了一次权限修复：
- 给当前用户补了一条「完全控制」权限项；
- 未改动任何文件内容，未改动所有者，未删除任何拒绝项；
- 备份与回滚脚本在 `G:\dsh-acl-report\`，回滚命令（如需）：

```powershell
pwsh -NoProfile -File 'G:\dsh-acl-report\acl-backup-e47e088983af48f79a649f03528b4915.json.ps1' -Path 'G:\python-learning' -AllowRoot 'G:\python-learning' -Restore 'G:\dsh-acl-report\acl-backup-e47e088983af48f79a649f03528b4915.json'
```

**副作用（重要）**：本次会话是在修复**之前**启动的，所以本会话内已经存在的 `README.md` 和 `.git\` 目录没有拿到新的权限项，AI 的受限终端**不能**修改它们（能读不能写）。

## 三、分工：谁跑什么命令

| 任务 | 谁来做 | 原因 |
| --- | --- | --- |
| `git add / commit / branch / push` | **你**（自己的终端或 VS Code 集成终端） | ① 沙箱限制；② 课程要求你亲手走完 Git 流程，教练只负责验收 |
| `pip install` / `uv add` | **你** | 沙箱不让写 `site-packages` 与临时目录 |
| `docker` / `docker compose` | **你**（阶段 2 起） | 同上 |
| 写练习代码、讲解材料、错题本 | **AI** | AI 可以正常写新建的文件 |
| 运行 `python xxx.py` / `pytest` 验证代码 | **AI 可以跑** | 只读 + 在新建目录里写缓存，没问题 |

**结论**：不影响教学。凡是「装东西」和「提交代码」都由你亲手做——这本来就是你要练的能力。

## 四、每次学习的固定工作流

```powershell
# 1. 打开终端，进入仓库
cd G:\python-learning

# 2. 激活虚拟环境（每天都要做）
.\.venv\Scripts\Activate.ps1

# 3. 确认解释器是 venv 里的那个
python -c "import sys; print(sys.executable)"
```

看到路径里出现 `G:\python-learning\.venv\Scripts\python.exe` 才算激活成功。

**首次使用前，先跑一次环境初始化脚本**（在你自己终端里，不要在 AI 沙箱里）：

```powershell
cd G:\python-learning
pwsh -File .\scripts\setup_env.ps1
```

如果提示「禁止运行脚本」：

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```
