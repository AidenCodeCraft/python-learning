# 03 · 阶段 1 节奏修订（2026-10-14 晚 · 基于 D1 实测数据）

> 触发：D1（10-14）实际用时 **3 小时**（计划 2h），且经过 1 次批改 + 6 处返工 + 1 轮复测才关账。
> 决策：用户选择"**不砍内容，自己加时间**"。本文把这个决定落成可执行的排期，并标出**止损开关**。

---

## 一、D1 实测数据（新预算的基准）

| 项目 | 计划 | 实际 |
|---|---|---|
| 题量 | 10 题 | 10 题 + 3 变式 + 4 复测 |
| 时长 | 2h | **3h**（20:00–23:00） |
| 返工 | 未计 | 1 次批改 + 6 处返工 ≈ 1h |
| 结果 | — | 档① 2/3、档② 3/3、档③ 0.5/4 → 复测 4/4 通过 |

**由此标定的三个系数**（后面所有排期都用它）：

1. 练习速度 ≈ **5 题 / 小时**（含卡住时间；档①档②快，档③明显慢）
2. 每个知识点日的**非练习开销** ≈ **1h**（间隔复习 15min + 讲解 25min + 复盘 20min）
3. **批改→返工 ≈ +0.5~1h / 天**（D1 出现过，必须进预算，不能当意外）

## 二、原计划 D2–D5 的缺口（按工作日 3h 计算）

| 日 | 内容 | 计划时长 | 按实测估算 | 缺口 |
|---|---|---:|---:|---:|
| D2 | 12 题 | 2h | 3.4h | −1.4h |
| D3 | 12 题 | 2h | 3.4h | −1.4h |
| D4 | 20 题 | 6h | 5.8h | +0.2h（缓冲极薄） |
| D5 | 8 个主题 + 项目 + 验收 | 6h | **10.8h** | **−4.8h** |
| **合计** | | **16h** | **23.4h** | **−7.4h** |

### 关键结论

> **即使工作日按 3h 算，D2/D3/D4 能装下，但 D5 装不下 —— 因为 10-18 之后就是阶段 2，没有第二天可借。**
> 所以 D5 的解法不是"加时间"，而是"**把内容搬家**"：把能提前学的搬到 D2/D3/D4。

---

## 三、修订方案：三条规则 + 内容前置

### 规则

1. **讲解 + 间隔复习挪到碎片时间**（午休/通勤，用手机看 README 与错题本）→ 每天回收约 40min。
   （原计划本来就有这条："上班时间只看讲解+示例和自检清单"，这次改为**强制执行**）
2. **D5 的 5 个知识点前置分散**到 D2/D3/D4（每天多 30~45min 微课），只留"必须整体做"的部分在 D5。
3. **每天留 15min 缓冲**给批改返工。

### 修订后的逐日安排

| 日期 | 碎片 40min（午休/通勤） | 晚间/白天主时段 | 产出 |
|---|---|---|---|
| **10-15 四** | D2 讲解 + D1 错题本"自测 5 问" | **3h15m**：D2 12 题（2.4h）+ 异常处理微课（30min）+ 复盘（20min） | `exercises/stage1/day02/` |
| **10-16 五** | D3 讲解 + D2 错题本 | **3h30m**：D3 12 题（2.4h）+ 文件读写与模块微课（45min）+ 复盘（20min） | `exercises/stage1/day03/` |
| **10-17 六** | — | **6h**：D4 20 题（4h）+ JSON 与 OOP 基础微课（1.25h）+ 复盘（30min） | `exercises/stage1/day04/` |
| **10-18 日** | — | **6h**：pytest×3（1.5h）+ async 认知（15min）+ `todo_cli` 项目（3h）+ **阶段 1 验收**（1.5h） | `projects/stage1/todo_cli/` |

**合计**：主时段 18.75h + 碎片 1.3h ≈ 20h（原计划 16h）。
**代价**：10-15 需比 3h 多 **15min**，10-16 需多 **30min** —— 这就是"自己加时间"的具体数字，其余靠碎片时间补。

### D5 内容为什么这样搬家（每条都能和当天主题天然衔接）

| 原属 D5 的知识点 | 搬到 | 为什么搭 |
|---|---|---|
| 异常处理 | **D2** | D2 的运算符天生抛异常：`10 / 0`、`int("abc")` |
| 文件读写 + 模块与包 | **D3** | 循环 + 文件是天生一对（逐行读文件） |
| JSON + OOP 基础 | **D4** | JSON 是 dict 的搭档；函数/作用域之后过渡到 `class` 最自然 |
| pytest + async 认知 + 项目 + 验收 | 留在 D5 | 只能整体做 |

## 四、不变量（不许破）

- 档① → 档② → 档③ **不跳档**；每档不过不进下一档。
- 每天 `CHECKLIST.md` **逐条打勾** + Git 提交（D1 的教训：清单说了算，记忆不算数）。
- 阶段 1 验收标准不变：8 类异常现场修正、3 个 pytest 跑通、100~150 行脚本、Git 分支 + 提交。

## 五、止损开关（提前定好，到时候不纠结）

| 检查点 | 触发条件 | 动作 |
|---|---|---|
| 10-16 结束 | D3 没做完 | 周六上午先补 D3；D4 砍掉"推导式"，改为随用随学 |
| 10-17 结束 | D4 没做完 | 周日 D5 只做 pytest + 项目；JSON/OOP 微课推迟到阶段 2 前 30min |
| 10-18 结束 | 阶段 1 验收没过 | 启动"方案 A"：借阶段 2 半天；阶段 2 砍 MySQL（只练 PostgreSQL），Redis 只练 String + Hash + ZSet |
