## 今天的核心模型：写循环前先答"三问"

```text
① 遍历什么？   → 数据源（列表？字符串 s？range？）
② 攒到哪儿？   → 累加器 / 结果变量（total、count、last_index…）
③ 从哪到哪？   → 起点、终点（range 的 stop 取不到！）
```

今天 4 道错题，正好一题踩一个坑 —— **ex09 错在 ①，ex08 错在 ②，ex04 错在 ③，ex10 错在"返回值用了常量而不是变量"**。

## 错题 1 · 把循环变量当累加器（ex08，今天最严重）

- **现象**：

  ```python
  def ex08_sum_to(n: int) -> int:
      for i in range(1, n):
          if n <= 0:
              return 0
          i += 1          # ← 改循环变量，等于白改
      return 0            # ← 永远返回 0
  ```

  实测 `ex08_sum_to(5) → 0`（应为 15）。
- **错因（三处，一个根）**：
  1. **没有累加器**。求和必须有 `total = 0` 这样的变量把每一项**攒起来**；`i` 只是"走到哪了"，改它没有任何意义（下一次循环会被 `range` 重新赋值）。
  2. `range(1, n)` **漏掉最后一项**（`stop` 取不到）→ 应为 `range(1, n + 1)`。
  3. 循环外面 `return 0` 把结果盖掉了；`if n <= 0` 的判断放在循环里也是错位置。
- **正确写法**：

  ```python
  def sum_to(n: int) -> int:
      if n <= 0:
          return 0
      total = 0                      # ① 累加器
      for i in range(1, n + 1):      # ② 边界：n 要取到
          total += i                 # ③ 攒起来
      return total                   # ④ 循环结束后返回
  ```
- **一句话记住**：**循环变量负责"走到哪"，累加器负责"攒到多少" —— 两个都要有。**
- **变式**：`variants.py` v1（`sum_odd_to`）

## 错题 2 · 循环遍历了"别的序列"（ex09）

- **现象**：

  ```python
  def ex09_count_vowels(s: str) -> int:
      count = 0
      for n in ["a", "e", "i", "o", "u"]:     # ← 遍历的是元音表，不是 s
          count += 1
      return count
  ```

  实测 `count_vowels("Hello World") → 5`（应为 3）。**结果和传进来的 `s` 毫无关系。**
- **错因**：我数的是"元音表里有几个字母"（永远是 5），而不是"`s` 里出现几个元音"。
  循环的**数据源应该是输入**，元音表是**用来判断的集合**（配角）。
- **正确写法**：

  ```python
  def count_vowels(s: str) -> int:
      count = 0
      for ch in s.lower():          # ① 遍历 s
          if ch in "aeiou":         # ② 用元音表做判断
              count += 1
      return count
  ```
- **一句话记住**：**遍历输入，拿规则去比对；不是遍历规则。**
- **自检方法**：换个输入看结果变不变 —— 如果 `count_vowels("xyz")` 还是 5，那一定错了。
- **变式**：`variants.py` v2（`count_digits`）

## 错题 3 · 用常量冒充下标（ex10）—— D1 的老毛病重现

- **现象**：

  ```python
  for i, t in enumerate(items):
      if t == target:
          return 1        # ← 应该 return i
  return -1
  ```

  实测 `find_first([5, 3, 7, 3], 3) → 1` **看起来对了** —— 因为题目给的数据里，`3` 恰好就在下标 1。
  换个数据立刻露馅：`find_first([1, 2, 3], 3)` 应该返回 **2**，我的代码返回 **1**。
- **错因**：把"**让这道题的输出对**"当成了"**解决问题**"。这是 D1 `ex07`（硬编码 `a = 2; b = 1`）的同一个病。
- **正确写法**：

  ```python
  for i, t in enumerate(items):
      if t == target:
          return i        # ← 变量，不是常量
  return -1
  ```
- **一句话记住**：**返回值里不许出现"只对当前测试数据成立"的常量。**
- **自检方法**：写完之后自己**换一组数据**跑一遍 —— 换数据还对，才算对。
- **变式**：`variants.py` v3（`find_last`，硬编码必挂）

## 错题 4 · 只改一半，而且没对自己的要求（ex04）

- **现象**：题目要求"用 range 的步长直接打出 **2 4 6 8 10**"，我写成：

  ```python
  for n in range(1, 11, 2):   # 步长改对了，起点没改
      print("ex04:", n)       # 实际打出 1 3 5 7 9
  ```
- **错因**：
  1. 只改了 `step`，没改 `start`；
  2. **没有拿输出对自己写下的要求**（docstring 明明白白写着"2 4 6 8 10"）。
- **正确写法**：`range(2, 11, 2)`（起点 2、终点开区间所以写 11、步长 2）。
- **一句话记住**：**改参数要一次改齐；跑完先读题目要求，再读输出。**
- **变式**：把"打印 1~20 里 3 的倍数"写一遍（步长法）。

## 错题 5 · demo 的 3 处预测没核对（老毛病第 N 次）

| 处 | 我写在注释里的 | 实际 |
|---|---|---|
| `1-a` `list(range(5))` | `[1, 2, 3, 4]` | **`[0, 1, 2, 3, 4]`**（漏了 0） |
| `3-a` `while i <= 5` 的累加 | `10 5` | **`15 6`**（那是 ex02 改成 `< 5` 之后的答案） |
| `6-b` `print(name, score)` | `[('Tom',90), ('Ann',85)]` | **`Tom 90` / `Ann 85`**（把 6-a 的答案抄过来了） |

- **错因**：输出就在屏幕上，但**没有逐行对着自己的预测读一遍**。
- **这一条已经连续出现：D2 三次、D3 又是三次。**
- **解法（从 D4 起强制执行）**：预测不要只写在注释里，用 `check()` 把"对上了吗"直接打印出来：

  ```python
  def check(label: str, actual: object, guess: object) -> None:
      print(label, "实际=", actual, "预测=", guess, "对上了吗:", actual == guess)
  ```

  **眼睛会漏，机器不会。** 今天 `variants.py` 顶部已经放好这个函数，D4 的骨架里也会内置。
