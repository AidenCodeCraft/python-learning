## 错题 1 · `UPDATE` 缺 WHERE（第 6 题）

- **现象**：
  ```sql
  UPDATE students SET score = score + 5;     -- 没有 WHERE
  ```
  你想改"二班所有人"，实际改了**全部 4 个人** → 影响 4 行（预期 2 行）。
- **连锁后果**：后面所有分数都错了 —— 第 10 题你记录"平均 91.00"，而预期是 **87.67**。
- **更严重的问题**：你的自检记录里写着"第 6 题：4"、平均分"91.00"，**数字和预期对不上，却在提交时说"无对不上"**。
  → 老毛病第 N 次：**跑完不逐条对照预期结果。**
- **正确写法**：
  ```sql
  UPDATE students SET score = score + 5 WHERE class_name = '二班';
  ```
- **一句话记住**：**写 UPDATE / DELETE 时，WHERE 是默认要写的，写完先回头看这一句有没有 WHERE。**
- **安全三步法**：先 `SELECT` 确认会改到谁 → 再 `UPDATE` → 再 `SELECT` 确认结果。

## 错题 2 · 事务回滚（你说"还不太会用"）

- **现象**：第 12 题里写了
  ```sql
  START TRANSACTION；            -- ← 全角分号，会报错
  UPDATE students SET score = score + 2;   -- ← 又缺 WHERE
  COMMIT;
  ```
- **本质**：事务的三个动作没建立画面感。记住这三句话就够：
  1. **`START TRANSACTION`**：从现在起，我的修改先"记在草稿"上。
  2. **`ROLLBACK`**：草稿撕掉，回到事务开始时的样子。
  3. **`COMMIT`**：草稿转正，**之后再也撤不回来**。
- **两条高频考点**：
  - MySQL 默认 `autocommit = 1` → 单条 `UPDATE` 会自动提交，所以"想回滚"必须**先显式开事务**。
  - **DDL（`TRUNCATE`/`DROP`/`ALTER`）会隐式提交** → 回滚不了。这是面试常问的坑。
- **动手**：跑一遍 [rollback-practice.sql](../../exercises/stage2/sql/day01/rollback-practice.sql)（10 分钟，两个 DBX 标签页）。**看一遍胜过背十遍。**
- **一句话记住**：**回滚只救"没提交的 DML"。**

## 错题 3 · 1NF 的例子

- **我的答案**：答不出 / 说不清。
- **正解**：**1NF = 每一列都不可再分（原子性）**。反例：
  ```text
  ❌ 一列存多个值：  phone = '138xxx,139xxx'
  ❌ 一列存"省市区"： address = '浙江省杭州市西湖区'
  ✅ 拆开：province / city / district 三列，或另起一张"电话表"
  ```
- **一句话记住**：**1NF 管"一格里只能放一个值"。**

## 错题 4 · 2NF / 3NF 各消除什么依赖

- **我的答案**：答不出。
- **正解**：
  | 范式 | 消除什么 | 例子 |
  |---|---|---|
  | **2NF** | **部分依赖**：非主键列只依赖**复合主键的一部分** | 订单明细表 `(订单id, 商品id) → 商品名`：商品名只依赖"商品id" ❌ |
  | **3NF** | **传递依赖**：非主键列依赖**另一个非主键列** | 员工表里有 `dept_id` 又有 `dept_name`：`dept_name` 依赖 `dept_id` ❌ |
- **一句话记住**：**2NF 治"半个主键就够用"，3NF 治"拐个弯才够用"。**

## 错题 5 · 聚簇索引 / 二级索引 / 回表

- **我的答案**：答不出。
- **正解**（用"书"打比方）：
  | 概念 | 一句话 |
  |---|---|
  | **聚簇索引** | 就是**主键索引**：B+ 树的叶子节点**直接存整行数据**（书本身按页码排好） |
  | **二级索引** | 其他索引：叶子节点存的是**主键值**（目录里写"第 5 章 → 第 88 页"） |
  | **回表** | 通过二级索引查到主键后，**再按主键去聚簇索引查整行**（按目录页码再翻一次书） |
- **为什么需要回表**：二级索引里只有索引列 + 主键，没有你要的其他列。
- **怎么避免**：**覆盖索引** —— 查询的列全在索引里（`EXPLAIN` 显示 `Using index`）。
- **一句话记住**：**聚簇索引存整行，二级索引存主键；二级索引要"回表"才能拿到其他列。**

## 错题 6 · 最左前缀

- **我的答案**：答不出。
- **正解**：联合索引 `(name, age)` 的排序规则是**先按 name 排，name 相同再按 age 排**。
  所以：
  - `WHERE name = '张三'` ✅ 能用
  - `WHERE name = '张三' AND age = 20` ✅ 能用
  - `WHERE age = 20` ❌ **不能用**（就像查字典只知道第二关键字）
- **一句话记住**：**联合索引只能从最左边开始用，跳过左列就等于没用。**

## 错题 7 · ACID 与实现机制

- **我的答案**：ACID 名词说得出，但"靠什么日志/机制"答不上。
- **正解**：
  | 特性 | 含义 | MySQL 靠什么 |
  |---|---|---|
  | **A 原子性** | 要么全做、要么全不做 | **undo log**（回滚日志） |
  | **C 一致性** | 从正确状态到正确状态 | **应用 + 约束**（不是某一种日志！） |
  | **I 隔离性** | 并发事务互不干扰 | **MVCC + 锁** |
  | **D 持久性** | 提交后断电不丢 | **redo log**（重做日志） |
- **一句话记住**：**A 靠 undo、D 靠 redo、I 靠 MVCC+锁、C 靠应用和约束。**

## 必须能脱口而出的 5 句话

1. `UPDATE` / `DELETE` **默认要带 WHERE**；写之前先 `SELECT` 确认会改到谁。

3. **DDL（TRUNCATE/DROP/ALTER）会隐式提交，不可回滚**；autocommit 默认开着。
4. 聚簇索引存整行、二级索引存主键、二级索引要**回表**；联合索引只能**从最左列**开始用。
5. A 靠 undo log、D 靠 redo log、I 靠 MVCC + 锁、C 靠应用 + 约束。
