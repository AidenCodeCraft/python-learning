## 今天的核心模型（所有错题都是它派生的）

```text
名字 ——指向——> 对象

q = ...         只动"名字这一端"：换个指向，对象本身没被动过
q.append(...)   只动"对象那一端"：就地改，所有指向它的名字都看得见
```

## 错题 1 · 把"换指向"当成了"就地改"

- **现象**：`ex01` 我把 `q = q + [4]` 的预测写成 `[1, 2, 3, 4] [1, 2, 3, 4] True`，实际是 `[1, 2, 3] [1, 2, 3, 4] False`；
  `demo 5-b` 我把 `r is t` 预测成 `True`，实际是 `False`。
- **错因**：我把"赋值"全当成一种动作。`q = q + [4]` 是**造一个新列表再让 q 改指向它**，`p` 从头到尾没被碰过；
  而 `t = r.copy()` 造出了第二个对象，所以 `r is t` 必然是 `False`。
- **正确写法**：

  ```python
  p = [1, 2, 3]
  q = p                # 别名：两个名字指向同一个对象
  q = q + [4]          # 只是让 q 换指向新列表
  print(p, q, p is q)  # [1, 2, 3] [1, 2, 3, 4] False
  ```

- **一句话记住**：**`=` 改的是名字，`.append()` 改的是对象。**
- **变式**：`b = b + [3]` vs `b.append(3)` —— `variants.py` v1 已答对 ✅

## 错题 2 · 以为 `.copy()` 连里面也复制了（今天最重要）

- **现象**：`demo 6-a` 我预测 `[[1, 2], [3]]`，实际 `[[1, 2, 99], [3]]`；`6-b` 我预测 `False`，实际 `True`。
  `ex09` 我写了 `snapshot[0]["status"]` **却没有赋值**，所以陷阱根本没复现出来。
- **错因**：`.copy()` 只新建**最外层容器**，里面装的对象仍是同一批。所以改内层会连累原数据 ——
  它不是"起了个新名字"，也不是"连里面一起复制"。
- **正确写法**：

  ```python
  snapshot = tasks.copy()
  snapshot[0]["status"] = "done"      # 少了这个 = ，什么都不会发生
  print(tasks)                        # 原列表也变了：内层 dict 是同一个对象

  snapshot = copy.deepcopy(tasks)     # 要真正独立，用 deepcopy
  ```

- **一句话记住**：**浅拷贝：外层是我的，内层是大家的。**
- **变式**：`variants.py` v2 / `retest.py` q1（deepcopy 版）、q2（别名版）—— 四格对照表要能默画。

## 错题 3 · 默认参数陷阱（阶段 0 遗留，本次已补上）

- **现象**：阶段 0 第 3 题"结论对、原因错"；本次 `ex05` 一开始也说不清为什么。
- **错因**：`def f(x, box=[])` 里的 `[]` **只在函数定义时创建一次**，之后每次调用共享同一个列表 —— 本质就是错题 1 的"别名"。
- **正确写法**：

  ```python
  def collect(item: str, box: list[str] | None = None) -> list[str]:
      if box is None:          # 判断"没传"，而不是"是不是空列表"
          box = []
      box.append(item)
      return box
  ```

- **一句话记住**：**默认值在定义时算一次；要"每次新的"，就用 `None` 占位，进函数再造。**
- **变式**：`variants.py` v3（dict 版）已答对 ✅；`retest.py` q3（`items = items + [x]` 版）**不累积** ——
  因为那一行是"换指向"，从没去动默认的那个列表。

## 错题 4 · "输出对了" ≠ "做对了"

- **现象**：`ex07` 写法 1 我写 `a = b - 1; b = a + 1`。教练实测：执行完 `a, b` 还是 `(1, 2)`，**根本没交换**；
  程序打印出的 `2 1` 全是写法 2 的功劳。
- **错因**：我把"让 `print` 看起来对"当成了"解决问题"。数据一换（a=5, b=9）立刻暴露。
- **正确写法**：

  ```python
  # 写法 1（C/Java 直觉，不用第三个变量）：加减法
  a = a + b
  b = a - b
  a = a - b

  # 写法 2（Python 风格）：元组解包 —— 右边先整体算成 (b, a)，再一起分给左边
  a, b = b, a
  ```

- **一句话记住**：**先问"换一组数据还对吗"，再问"输出对不对"。**
- **变式**：拿 `a = 5, b = 9` 把写法 1 的两行旧代码走一遍，看它还交换不交换。

## 其他两个小坑（看一眼就行）

- `bool == int` 是在比较两个**类对象**。要问"实例属不属于某个类"用 `isinstance(True, int)` → `True`；
  顺带：`True + True` → `2`，因为 `bool` 继承自 `int`，`True == 1`。
- `ex06` 用 `deepcopy` 复制一维 list：结果对，但没必要。一维用 `m.copy()`；`deepcopy` 留给嵌套结构。

## 必须能脱口而出的 4 句话

1. `x = 10` 是"造一个对象 10，让名字 `x` 指向它"，**不是**"把 10 放进盒子 `x`"。
2. `=` 改的是**名字**（换指向）；`.append()` 改的是**对象**（就地改）。
3. 不可变的"改" = **换对象**；可变的"改" = **改对象**。
4. 别名：改一个另一个也变；浅拷贝：外层独立、内层共享；要彻底独立用 `deepcopy`。
