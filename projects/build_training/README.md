# 从零构建训练营（2026-10-20 起 · 每个晚上 40~60 分钟）

> **为什么有这个营**：你 D1–D4 的 50 多道填空题几乎全对，但 `todo_cli`（3 个文件、11 个 TODO）无从下手。
> 原因不是能力，是**从来没练过"从零构建"**（见 [05-为什么能看懂却做不出来](../../notes/05-为什么能看懂却做不出来.md)）。
>
> **目标**：本周结束，你能对着一个需求，**先写出设计、再独立写出 60~100 行的完整程序**。
> **位置**：白天 7 小时学 SQL（考试），**晚上这 2 小时专门做构建训练** —— 两边不抢。

## 四段式训练安排

| 段 | 日期（晚上） | 内容 | 你要交什么 |
|---|---|---|---|
| ① **设计** | **10-20 二** | 3 个需求的"三段设计"（**不写代码**） | 3 份设计卡 |

## 三段设计法（每天都要用，先写这个再动代码）

```text
① 数据长什么样？
   举一个具体例子，最好直接写出 JSON / 列表的样子。
   例：[{"word": "hello", "count": 3}, ...]

② 分几个部分？各自职责一句话。
   例：
     counter.py  —— 读文件 + 数词 + 排序（不打印）
     main.py     —— 解析参数、调用 counter、打印（不读文件）

③ 分几步做？（伪代码，5~8 步）
   1. 读文件，拿到全部文本
   2. 按空格切词
   3. 用 dict 数每个词出现几次
   4. 按次数排序
   5. 取前 5
   6. 打印
```

**写不出这三段 = 还没想清楚 = 不许写代码。** 先问教练。

---

## 四条铁律

1. **设计没过，不写代码。**（这条是治你"直接伸手写代码"的根）
2. **抄的时候每行都要自己敲** —— 允许看参考，**禁止复制粘贴**。
3. 每天开始前 **10 分钟复习前一天的产物**（读一遍自己的注释）。
4. 卡住时先写"我卡在第几步 + 我的思路"，再问我。**连续两次卡住，我才升一级提示。**

---

## 为什么这套对你有用（和你公司的情况有关）

你上周末的"飞机大战"考试，同事都是 AI 做出来的，你也用 AI 过了。

**这不丢人** —— 现在工程师都用 AI。但有个事实要看清：

> **AI 能生成代码，不等于你能维护代码。**
> 公司真正缺的是"**能看懂 AI 产出、能改、出问题能定位**"的人。
> 这正是四段式的价值：**读 → 抄 → 改** 三段直接对应"看懂 → 复现 → 维护"，最后一段"造"才是独立开发。

所以本周的训练重点不是"背语法"，而是**读懂结构 + 动手改**。

## 每天的流程（固定 50 分钟）

| 分钟 | 做什么 |
|---:|---|
| 0–5 | 复习昨天的产物（读自己的注释/代码） |
| 5–10 | 读今天的任务说明 |
| 10–40 | 做任务（设计 / 抄 / 改） |
| 40–50 | 自检 + 写 3 行复盘（今天学到什么、卡在哪、明天要注意什么） |
| 之后 | 发我检查 |

---

## 我会怎么检查

- **设计卡**：只看"照着它能不能写出代码"，不看你写得多漂亮
- **抄写版**：注释是否说清"这行在干嘛、数据从哪来"，手抄版能否跑通
- **改造版**：功能是否真加上、旧功能是否没被改坏

> 每天 40~60 分钟，三天后你会发现：**代码不是"想出来的"，是"按设计一步步长出来的"**。
